# Changelog — 2026-08

> Append-only. One line per change, newest last within a day.

## 2026-08-09

- **Design review (v2 architecture)** — 13-turn first-principles review of the product definition, primitives, and structure. Produced ADR-0018 … ADR-0031 on branch `feat/v2-architecture`.
- ADR-0018 — Engram redefined: a human knowledge system where the agent does the organizing. Explicitly **not** agent memory, **not** a context-window fix, **not** a better Obsidian.
- ADR-0019 — Primitives reduced to **Node + Edge**. `type`, `tags`, folders, MOCs, citations, attachments all shown to reduce to one of the two. Any structure = a choice of which edges get authored.
- ADR-0020 — **Adopt OKF v0.2**, superseding ADR-0002. Time and Provenance retired by the spec (`sources`, `generated`, `verified`, `stale_after`, `status`); engram adds only `supersedes`.
- ADR-0021 — Identity model: slug is identity, path is address, `aliases` in the moved file. Central redirect ledger rejected (multi-device write contention). Supersedes path-is-identity.
- ADR-0022 — Typed relations live in frontmatter, not markdown links. Closed-type rule: **no code, no closed type**. Closed set today is two (`supersedes`, `sources`). Amends ADR-0003.
- ADR-0023 — One human-chosen physical tree plus generated views. Corrects an earlier overclaim that structure is purely a view. Extends ADR-0006.
- ADR-0024 — Three-tier dependency inversion (core / policy / detail); adapters may only add affordances. Extends ADR-0011 and ADR-0015.
- ADR-0025 — Detection over configuration. Config cannot grant a capability; it only announces what is missing.
- ADR-0026 — Validation gates promotion, never capture. Amends ADR-0008's rejection behavior — mobile capture with no frontmatter is inbox, not an error.
- ADR-0027 — Relations extracted at **write time only**, never post-hoc. Four mitigation layers, two supplied free by OKF v0.2.
- ADR-0028 — Obsidian owns link rewriting; engram verifies only. Highest operational risk in the system, unrelated to any primitive.
- ADR-0029 — Derived state is never committed; regenerate, never merge.
- ADR-0030 — Boundaries are repositories, one per distinct set of humans who may see all of it. No visibility model, no lens, no permissions. Retires four of six originating requirements with zero code.
- ADR-0031 — Two evidence gates before graph investment, each able to end the project. Gate 1 threshold: <20% structural query traffic → stop.
- `specs/vision/problem-statement-v2.md` — new canonical problem statement; supersedes the framing in `project-charter.md`.
- `specs/planning/roadmap.md` — rewritten for the v2 line: Phase 7 (Evidence/Gate 1) → Phase 12 (Obsidian surface). **Phase 5 (Semantic Layer) cancelled**, superseded by Phase 11.
- TD-004 filed — the concept walker has no notion of a nested vault root, so a parent `reindex` would descend into a nested vault and publish its descriptions into a shared index.
- FEAT-003 / FEAT-004 filed — skills and guardrails as Tier-2 Agency concerns, post-v2.

## 2026-08-10

- **Architecture + intelligence pass.** Five ADRs (0032–0036) on branch `feat/v2-architecture`.
- ADR-0032 — Internal model (`core/model.ts`) + versioned codecs (`format/okf-v0_N.ts`) + a codec registry. Fixes a real OCP violation (`core/okf.ts` would be edited on every spec release) and a DIP violation (core types mirroring an external YAML schema). Also splits the fat `substrate` interface into narrow ports — `FileStore`, `Detector`, `Clock` — for interface segregation. Closed relation types become a registry, not a switch in the gate.
- ADR-0033 — `format(content, hints)` takes content, not a path. Capture is a durability step, not a prerequisite; `inbox/` is a buffer, not a pipeline stage. Found via the case "I hand raw notes to the agent and say format this" — there is no file to capture.
- ADR-0034 — Engram ships no encryption and no network. Encryption at rest is a substrate concern (full-disk, private repo, `git-crypt` on specific paths); an encrypted note is a note engram cannot help with. Names the threat that actually changed: **the agent is a network egress path**, answered by ADR-0030's separate repo, not by encryption.
- ADR-0035 — User memory is a second store at `.engram/memory/`, using ADR-0019's primitives unchanged: an observation is a node, a pattern is a node whose `sources` are the observations supporting it. Gitignored by default; `rm -rf` is safe by construction. High-volume events use a compact JSONL log; only distilled patterns become nodes.

Inference ranked by *would a correct answer change behavior*: retrieval gaps, re-derivation, contradiction, staleness × intent, dead weight, then rhythm/calendar last (least differentiated, demos best). ## v0.7.0 — Phase 8: Core (2026-08-12)

- **BREAKING.** The v1 CLI and library surface are removed. `src/` was replaced clean-room: 40 files / ~4,212 LOC and 229 tests deleted, 20 files and 171 tests written in their place. No v1 code was carried forward.
- **Node + Edge are the only primitives** (ADR-0019). A node **may be empty** — a link to an unwritten note is a valid node, not an error.
- **Internal model behind versioned codecs** (ADR-0032). `format/okf-v0_1.ts`, `okf-v0_2.ts` and a registry that dispatches on `okf_version`. Adding a version is adding a file — proven by a test that registers a stub codec at runtime.
- **Narrow ports** — `FileStore`, `Detector`, `Clock`, each stubbable alone. Every port is total: a missing file reads as `null`, an unknown fact as `false`.
- **Identity** (ADR-0021): address is path, identity is the slug, move trail is `aliases:` on the node itself. Slug collision and missing slug are **warnings**, never errors.
- **Relations are a registry, not a switch** (ADR-0022/0032). Every closed type must carry validity semantics *and* a detective form. An unregistered kind never invalidates anything.
- **`capture` never rejects** (ADR-0026) — proven against a 15-case adversarial set. **`link`** passes a minimal validation gate; a rejection names the rule that fired and leaves the file byte-identical.
- Both architecture rules from v2-overview §2 are **lint-enforced and proven to fire**. Verifying them caught a real defect: eslint flat config is last-wins per rule, so the broad block was silently leaving `core/` unguarded.
- BUG-001's percent-encoding matrix and frontmatter parsing totality were **re-specified as tests** rather than ported as code, so a shipped fix was not reintroduced as a fresh bug.
- **Not in this release**: `format`, `recall`, `reindex`, `doctor`, `init`, `migrate`, adapters, MCP. Phases 9–11.

- **Phase 9 — Structure, views & health started** (branch `phase-9-structure`, target v0.8.0). `init` scaffolds the default tree, `reindex` regenerates derived state, views project edges, `doctor` reports integrity read-only.
- Two findings at plan time. **`part-of` does not exist** — the roadmap assumed it, but Phase 8 registered only `supersedes` and `sources`, so registering it is a Group 0 prerequisite under ADR-0022. And **two of ADR-0023's four named views cannot be built**: `by-tag` needs tag extraction (Phase 10) and `unread-sources` needs a notion of "read" absent from the model. Both deferred with reasons; `orphans` added in their place.
- Scope decisions: `init` ships one tree rather than presets; `doctor` is read-only with `--fix` deferred; nested vault roots are refused loudly on an explicit `.engram/` marker only, closing **TD-004**.

## v0.9.0 — Phase 10: Agent surface, write path (2026-08-12)

- **`engram format`** — the agent's main verb. Content plus the structure the agent decided become validated nodes and relations. Deterministic: slug from title, path from container, same input → same output.
- **Engram does not extract.** ADR-0034 forbids network calls, so engram cannot call a model; ADR-0019 assigns extraction to the agent, which knows the relationship when it writes the content. There is no extractor in `src/`, and **Gate 2 therefore measures the agent, not engram**.
- **Six guardrails, each in two halves** — `no-delete`, `require-sources`, `no-supersede-verified`, `propose-only`, `path-scope`, `rate-limit`. Preventive at the write gate, detective in `doctor`. The `Guardrail` type requires both, so a preventive-only rule does not compile.
- **`tighten()` cannot loosen**: `enabled` unions, `pathScope` **intersects**, `rateLimit` takes the minimum. A union on `pathScope` would let a downloaded skill grant itself the filesystem. Settled before skills exist (Phase 15).
- **`AGENTS.md` is generated** from the live relation and guardrail registries, not hand-written. A newly registered relation appears with no template edit. Not gitignored — an agent at a fresh clone needs the contract before it can run anything.
- **ADR-0040** — Gate 2's thresholds, fixed before any edge was sampled: **directionality ≥95%, predicate ≥90%**. Two bars because a reversed direction inverts meaning while a wrong predicate merely degrades traversal; one combined bar would let a 70%-directionality run pass on 99% predicate accuracy.
- **Gate 2 instrumented**: 24 ADRs formatted through the real path → 48 edges, sampled and worksheeted. **No verdict** — the report refuses one without blind human judgement, enforced in code.
- **Bug fixed, found by smoke-testing the binary**: preventive guardrails were implemented, tested and wired into `doctor` — but never connected to the gate. `format` wrote what it should have refused, and every test passed, because no test crossed the seam between the rules and their caller.
- **Phase 8 defect fixed**: no serialized file ended with a newline. The complete fix is an invariant — the writer adds one, the reader strips one — so `read(write(x))` does not drift.
- **Phase 15 added to the roadmap** (skills, MCP, adapters), and the Phase 10 brainstorm's claim that a failed Gate 2 would waste them is **corrected**: they sequence and expose operations Gate 2 does not affect.
- 373 tests, up from 269.

- **Phase 15 — Surfaces started** (branch `phase-15-surfaces`, target v0.10.0). Skills, MCP server, agent adapters. **Not gated on Gate 2** — everything here sequences or exposes operations that work regardless of the edge-accuracy verdict.
- **MCP ships over stdio and HTTP**, at the owner's direction. ADR-0034 requires revisiting the trust boundary *before* any network surface exists, so **ADR-0041** lands first. Engram's security story has been structural — nothing listens, so there is nothing to attack — and an HTTP server ends that. Three constraints: opt-in only, `127.0.0.1` by default, and a startup warning naming the exposed root.
- Finding at plan time: **engram does not execute skills.** v2-overview §6 makes a skill instructions rather than code, so there is no interpreter to build — engram discovers, validates and exposes, and the agent follows. Skills therefore map to MCP **prompts**, not tools; exposing them as tools would imply engram runs them.
- Found at phase start: **`commander` and `yaml` are dead dependencies.** Phase 8's clean-room rewrite hand-rolled both the argument parsing and the YAML subset, and neither package has been imported since — but `package.json` still ships both to anyone installing engram.

## v0.10.0 — Phase 15: Surfaces (2026-08-12)

- **Skills** — `.engram/skills/*.md` plus two built-ins. Engram **never runs a skill**: it discovers, validates and exposes, and the agent follows the instructions. A skill declaring an operation engram does not have is rejected at load, naming it and listing what exists — which is what makes §6's "can only sequence the seven operations" real rather than a sentence.
- **`engram skill list` / `engram skill new`** — the scaffold teaches the constraint, not just the shape.
- **MCP server over stdio and HTTP.** Operations are tools; **skills are prompts**, because engram executes the former and not the latter. One `handle()`, two transports, proven by a real `fetch` beside a real stdio exchange.
- **ADR-0041** — the MCP surface amends ADR-0034's trust boundary, landed **before** any HTTP code. Three constraints, each a test rather than a default: **opt-in only**, **`127.0.0.1`**, and a **startup warning naming the exposed root**. No authentication — stated as a known limit, not discovered later.
- **Agent adapters** emit native pointers and no contract content, enforced by a test that checks four real `AGENTS.md` claims appear in neither pointer. Adding an agent is adding a descriptor.
- **Zero runtime dependencies.** `commander` and `yaml` had been shipping to every installer since Phase 8 deleted their last consumer (TD-005). The MCP layer is five JSON-RPC methods written directly rather than an SDK plus its tree.
- **Security bug caught by testing from the spec's own example**: `guardrails: [require-sources]` — §6's shorthand — parsed to *nothing*, so a skill asking to be constrained would have run unconstrained. Silent loosening.
- **Fourth wiring gap found by running the built artifact**: `policy/` and `surface/` were missing from the library exports. Same pattern as Phase 9's codec, Phase 9's `list()`, and Phase 10's ungated guardrails — unit tests passed, and nothing tested the seam.
- **FEAT-003** in progress → skills shipped. **FEAT-004** resolved. **TD-005** resolved.
- 450 tests, up from 373.

## 2026-08-23 — v0.13.0: upgrade path and vault provenance

- **`engram upgrade`** — reports what an older vault should change; `--apply` does
  the safe half. Reports before acting, and **never moves your notes**: `inbox/` →
  `raw/` is handed to you as a `git mv`, which keeps history a copy would lose.
  Copies rather than deletes, and prints the exact `git rm` for the leftovers.
- **`createdWith` in `.engram/config.json`** — a provenance stamp, preserved across
  structure changes because it answers what built the vault, not what last touched
  it. `doctor` reports skew by series and says plainly that notes are safe, since
  each carries its own `okf_version` and is read by a matching codec.
- Nothing about upgrading is required — every legacy location is still read.
- 670 tests.

## 2026-08-23 — ADR-0044: adopt the Agent Skills standard

- Researched how agents actually load skills. There is an **open standard**
  ([agentskills.io](https://agentskills.io/specification)) — a directory containing
  `SKILL.md`, `name` and `description` required, everything else under `metadata` —
  supported by Claude Code, Cursor, Codex CLI, the Gemini CLI and others. Skills in
  an agent's own directory are slash-invocable **and** model-invocable, with no MCP.
- Engram invented a parallel format and delivers only over MCP, so its skills work
  in engram and nowhere else. ADR-0044 accepts moving to the standard and rendering
  skills into each agent's directory via the existing adapter registry.
- Decided: **copies not symlinks** (one generator, every copy regenerated — the
  ADR-0017 argument; symlinks break on Windows, archives and sync services);
  **project-local not personal** (`~/.claude/skills/` would leak one vault into every
  project); **provenance marker not namespacing** (engram owns what engram wrote,
  and `/engram-connect-the-dots` is a permanent tax to avoid a solvable collision).
- Filed as FEAT-009. Not implemented yet.

## 2026-08-23 — Phase 17 brainstormed: Portable skills

- Phase 17 planned on branch `phase-17-portable-skills`, targeting v0.14.0. Implements
  FEAT-009 — engram's skills are reachable only over MCP and use a format engram
  invented.
- **ADR-0044's collision decision is amended.** Research into how agents actually load
  skills found that a folder under a skills directory containing
  `.claude-plugin/plugin.json` loads as a plugin with **no marketplace and no install
  step**, namespaced by the platform. So engram ships as a skills-directory plugin and
  gets `/engram:format` without inventing a prefix. ADR-0045 records it.
- **The namespace is the differentiator**: `/engram:<name>` is engram's, `/<name>` is
  yours. `engram/skills/` is source; every agent directory is a render target.
- **Protection is regeneration, not permission.** Built-in skills cannot be locked —
  engram's premise is plain files you own. Rendered skills are derived state, `reindex`
  overwrites them, `doctor` warns, and override-by-name means nobody needs to edit
  engram's copy. Read-only file modes rejected (Windows, sync services, `git clone`).
- Three gaps found by inspection and taken into scope: `AGENTS.md` never says **how**
  to invoke an operation; there is **no vault-root discovery** (`engram capture` from
  `concepts/` created `concepts/raw/`); and a rendered `SKILL.md` would be **indexed as
  a knowledge node** — BUG-008's shape for the third time.
- Operations stay six. Each gets a skill *about* it; a seventh operation named "skill"
  would make engram interpret skills, which §6 forbids.

## 2026-08-23 — Phase 17 Group 0: the plugin mechanism, verified

- **T0.1 was a gate and it earned its keep.** `claude plugin validate` passed on the
  exact structure engram will generate, and a session listed `engram:probe` beside an
  unprefixed `loose-probe` — the namespace decision demonstrated, not assumed.
  Auto-discovery did not fire under `claude -p`, which the reference explains: project
  -scope plugins load only after the workspace trust dialog, and `-p` is insufficient.
- Two host constraints found that the plan did not know about: the **one-time trust
  acceptance**, and that project-scope plugins **do not walk up to the repository
  root**. Engram cannot fix a host rule, so `doctor` and the contract will say so.
- All three agents researched before any was declared: `.claude/skills/`
  (plugin-capable), `.antigravity/skills/`, `.gemini/skills/`. Each descriptor carries
  a `verified` string, and a test asserts every target has one — ADR-0044's "will not
  write where it cannot verify it is read" made mechanical rather than prose.
- **ADR-0045** amends ADR-0044 §Collisions: the host provides the namespace, so engram
  invents nothing. `/engram:format` where a plugin concept exists, `/engram-format`
  where it does not, `/your-name` always. Protection is regeneration, not permission.
- ENH-008 filed: ADR-0044's stated reason for avoiding `.agents/skills/` is falsified
  for the Gemini CLI, which reads it at both tiers and gives it precedence. The
  conclusion stands; the justification needed correcting.
- `npm run check` green — 682 tests across 39 files, both smoke checks.

## 2026-08-23 — Phase 17 Group 1: the skill format becomes SKILL.md

- Engram's `uses`, `emits` and `guardrails` move under `metadata`, as the Agent Skills
  standard provides for. **The validation is unchanged — only its location moves**, and
  the tests pin that: an unknown operation is still rejected with its name, and the
  load-bearing array-before-object ordering in the guardrail reader is still asserted.
- The legacy single-file layout and the legacy `.engram/skills/` location are both
  still read, so a vault written by an earlier engram keeps working.
- `parseSimpleYaml` gains one level of nesting — it previously read `metadata:` plus
  indented keys as a null `metadata` and top-level keys, a silent misparse. A lookahead
  keeps `aliases:` reading as null, making it a strict superset for flat documents.
- `yamlScalar` quotes on write and `parseScalar` unescapes, because a `SKILL.md` is
  parsed by other agents with real YAML engines. OKF's tolerance of unquoted prose was
  only ever safe because engram is its sole reader.
- `serializeSkill` is the single generator every rendered copy goes through — the
  ADR-0017 argument applied to skills, so no copy can be more real than another.
- `engram upgrade` migrates a flat skill to `<name>/SKILL.md`, both hops at once for a
  vault that skipped a release. The **declared name wins over the filename**.
- Found and fixed: a freshly created vault reported needing an upgrade, because `init`
  still wrote the flat layout. Caught by a test asserting a property rather than a path.
- `npm run check` green — 708 tests across 40 files.
