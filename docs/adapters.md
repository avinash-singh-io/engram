# Agent adapters

> How engram reaches an agent — the contract it reads, the skills and commands it
> invokes — and how to add the next agent with evidence instead of hope.
> Descriptors live in [`src/surface/adapters.ts`](../src/surface/adapters.ts).
> See ADR-0011, ADR-0017, ADR-0044, ADR-0045, ADR-0046.

## The model

Every supported agent reads the **same vault**. Three kinds of files are rendered,
all regenerated by `engram reindex` from single sources, so no copy can drift:

| Render | Source | Where it lands |
|---|---|---|
| **The contract** (`AgentDescriptor.contractFile`) | one generator in `agents-md.ts`, fed by guardrails + structure + skills | each agent's own instructions file; omitted when the agent reads `AGENTS.md` natively |
| **Skills** (`skills?: SkillTarget`) | `engram/skills/` (the vault's own source) + one skill per operation from the registry | `<skills-dir>/<name>/SKILL.md`, prefixed `engram-<name>` where the host has no plugin concept |
| **Commands** (`commands?: CommandTarget`) | the operation registry alone | `<commands-dir>/engram-<operation>.md`, invoked `/engram-<operation>` |

Two rules hold everywhere:

1. **If it carries engram's mark, engram wrote it.** `/engram:format` where the
   host namespaces (Claude Code plugins), `engram-format` where it does not.
   Your own skills are never prefixed.
2. **Rendered files are derived state** (ADR-0029): edit one and `reindex` takes
   the edit back. Edit the file under `engram/skills/` instead — or for commands,
   don't: they have no user-editable source. `doctor` names this when you try.

## Registered agents

| Agent | Contract | Skills | Commands |
|---|---|---|---|
| `claude` | `/CLAUDE.md` (full copy) | `.claude/skills/engram/skills/<op>/` → `/engram:<op>` | — |
| `antigravity` | `/.antigravity/AGENTS.md` (full copy) | `.antigravity/skills/<prefix><name>/` | — |
| `gemini` | `/GEMINI.md` (full copy) | `.gemini/skills/<prefix><name>/` | — |
| `opencode` | none — reads root `AGENTS.md` natively | `.opencode/skills/<prefix><name>/` → skill tool | `.opencode/commands/engram-<op>.md` → `/engram-<op>` |

Skills are always **agent-invoked**; commands exist because some hosts also have a
**user-invoked** surface. An agent gets a target only once someone has watched a
file load from it — every descriptor's `verified:` field records that watching,
and `engram doctor` prints the table above per vault.

## Adding a new agent

A new agent is **a descriptor plus evidence**, not a fork and not a template.
The checklist, in order:

1. **Probe before code.** Hand-write one minimal `SKILL.md` into the agent's
   documented project-skills directory of a scratch vault (and one command file,
   if it has commands), open a real session, and record what loaded:
   `specs/phases/<phase>/evidence/t0-discovery-probe.md`. If discovery diverges
   from documentation, stop here and adjust the plan.
2. **Add the descriptor** to `AGENTS` in `src/surface/adapters.ts`: `contractFile`
   only if the agent needs its own copy of the contract; `skills` / `commands`
   targets with `verified:` reading *"pending"* until step 5. Derived helpers
   (`skillPath`, `commandPath`, walker exclusions) pick it up automatically.
3. **Pin the emitted tree**: extend the surface tests (see
   `tests/surface/command-targets.test.ts` for the registry invariants) and add
   checks to `scripts/smoke-opencode.mjs` or its sibling so the built binary is
   asserted, not just the functions.
4. **Render it**: `engram reindex`. Confirm `doctor` lists the new row.
5. **Watch it load** in a real session at the vault root. Record what was seen in
   an evidence file, then replace the descriptor's *"pending"* with the date and
   the evidence pointer. This is the step that turns documentation into a promise
   (ADR-0044: engram writes only into directories it has verified are read).

What is deliberately refused: home-directory scopes (machine-wide leaks), any
path whose loading has not been watched, and a second contract file for agents
that read `AGENTS.md` natively — that file would exist only to be maintained.
